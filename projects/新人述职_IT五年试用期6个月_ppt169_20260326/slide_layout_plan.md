# Slide Layout Plan

## 01_cover

- Page Goal: 用一句话建立汇报定位，传达“已完成阶段性证明”
- Layout Type: 大标题封面 + 右下角信息块
- Recommended Structure:
  - 顶部左侧：主标题
  - 标题下方：副标题
  - 页面中下部：一句核心结论条
  - 右下角：姓名、岗位、入职时间、汇报日期
- Visual Notes:
  - 白底，左上到右下浅蓝渐变几何底纹
  - 主标题使用深蓝，结论条使用浅蓝底深蓝字
  - 不放复杂图形，突出克制和专业感

## 02_toc

- Page Goal: 让评委快速理解汇报路径
- Layout Type: 四段式目录导航
- Recommended Structure:
  - 顶部：页标题 + 小结论条
  - 中部：4个横向目录卡片
  - 每个卡片包含：章节名、1句说明、对应编号
- Card Content:
  - 01 个人背景与岗位认知
  - 02 整体产出与关键案例
  - 03 个人沉淀与不足
  - 04 未来计划与转正申请
- Visual Notes:
  - 卡片采用浅灰蓝底，编号使用大号蓝色数字
  - 当前页不需要图表，重点是路径清晰

## 03_chapter

- Page Goal: 展示个人背景、岗位定位和职责边界
- Layout Type: 左时间轴 + 右标签卡片
- Recommended Structure:
  - 左侧 40%：纵向时间轴
  - 右侧 60%：岗位信息卡 + 能力标签区
- Left Timeline:
  - 教育背景
  - 过往工作经历
  - 入职当前公司
  - 当前负责方向
- Right Content:
  - 岗位：后端研发
  - 业务方向：会员、营销活动、运营平台
  - 能力标签：复杂需求拆解、平台化设计、项目统筹、AI协同研发
- Visual Notes:
  - 时间轴节点用蓝色圆点
  - 标签区可使用 2 x 2 能力标签块

## 04_role_transition

- Page Goal: 说明岗位理解和试用期目标
- Layout Type: 三列目标卡 + 底部总结条
- Recommended Structure:
  - 顶部：页面标题 + 结论句
  - 中部：3张并列目标卡
  - 底部：一句阶段总结
- Three Cards:
  - 快速熟悉业务并独立承接需求
  - 在关键项目中承担更大责任
  - 把一次性交付沉淀成可复用机制
- Visual Notes:
  - 三卡片建议使用同宽布局
  - 每张卡片上方放一个小图标：target、users、server

## 05_6m_kpi

- Page Goal: 用数据说明整体产出和结果质量
- Layout Type: KPI卡片 + 底部证据说明
- Recommended Structure:
  - 顶部：页面标题 + 一句话结论
  - 中部：4张 KPI 卡片
  - 底部：补充说明条
- KPI Cards:
  - 查询接口优化：8s → 500ms
  - 节日活动首期：19个工作日上线
  - 积分提醒覆盖：40w+ 用户推送
  - 转盘配置化：新增活动 1天 → 2h
- Bottom Insight:
  - 结果覆盖性能、交付效率、系统支撑能力与复用价值
- Visual Notes:
  - 4张卡片用 2 x 2 排布
  - 数字做大，描述做小，箭头趋势用 Accent 色强化

## 06_project_cases

- Page Goal: 展示圣诞与新年活动的复杂项目交付能力
- Layout Type: 左时间轴 + 右项目说明
- Recommended Structure:
  - 左侧：四期项目时间轴
  - 右侧：项目背景、职责、难点、结果四块内容
- Left Timeline:
  - 11.03 - 11.27 第一期上线
  - 中期迭代推进
  - 圣诞节点交付
  - 12.23 完成第四期发布
- Right Blocks:
  - 项目背景：拉新、活跃、转化三重目标
  - 个人职责：项目负责人 + 核心研发
  - 项目难点：时间紧、任务重、协同复杂
  - 项目结果：四期按期落地
- Visual Notes:
  - 时间轴适合用横向 milestone
  - 右侧四块内容可用 2 x 2 小卡片

## 07_problem_analysis

- Page Goal: 展示规则引擎从0到1的独立建设能力
- Layout Type: 闭环流程图 + 右侧价值总结
- Recommended Structure:
  - 左侧 65%：从原型到落地的闭环流程
  - 右侧 35%：项目价值与个人能力总结
- Left Flow:
  - 原型设计
  - 需求文档
  - 系统设计
  - 后端实现
  - 测试执行能力
- Right Summary:
  - 业务价值：规则配置可视化、多环境管理、测试执行
  - 能力体现：抽象设计、全流程 ownership、独立交付
- Visual Notes:
  - 推荐使用 5 步流程箭头图
  - 右侧用深浅两层卡片区分业务价值和个人价值

## 08_improvement_actions

- Page Goal: 展示优化和平台化建设带来的长期价值
- Layout Type: 三栏案例对比页
- Recommended Structure:
  - 顶部：页面标题 + 结论句
  - 中部：3张并列案例卡
  - 底部：统一总结条
- Three Cases:
  - CRM 查询优化
  - 签到重构
  - 转盘配置化
- Each Case Card:
  - 背景问题
  - 核心动作
  - 结果提升
- Suggested Highlights:
  - 查询性能：8s → 500ms
  - 签到重构：后端标准配置化，减少重复开发
  - 转盘活动：33个子类问题收敛到配置组合
- Visual Notes:
  - 三栏布局最适合这一页
  - 每张卡片底部放一个小的 before/after 对比区

## 09_next_6m_plan

- Page Goal: 展示岗位之外的额外贡献与团队沉淀
- Layout Type: 左侧成果列表 + 右侧价值映射
- Recommended Structure:
  - 左侧：做了什么
  - 右侧：解决了什么问题
- Left Content:
  - 编写后端研发新人指引
  - 梳理新增工程应用 SOP
  - 梳理上线应用 SOP
  - 实践 AI 协同研发方法
- Right Content:
  - 加速新人融入
  - 降低重复沟通成本
  - 提高流程确定性
  - 沉淀团队复用资产
- Visual Notes:
  - 左右两列中间用箭头或连接线建立映射关系
  - 适合用清单 + 价值标签的咨询风表达

## 10_risk_support

- Page Goal: 客观展示不足，并给出具体提升路径
- Layout Type: 三行问题改进表
- Recommended Structure:
  - 顶部：页面标题 + 结论句
  - 中部：3行表格，每行包含不足、影响、改进行动
- Three Rows:
  - 结果量化不充分 | 复盘说服力不足 | 提前定义效果指标
  - 业务纵深有待加强 | 方案判断还可前置 | 系统梳理会员与营销链路
  - 团队级 AI 规范不足 | 经验难复用 | 建设项目级 context 和协作规范
- Visual Notes:
  - 用三段式横向表格最清晰
  - 不足用灰色，行动用蓝色，避免页面情绪过重

## 11_value_summary

- Page Goal: 展示未来6个月计划，并顺带提出建议与求助
- Layout Type: 上时间轴 + 下支持事项
- Recommended Structure:
  - 上半区：未来6个月里程碑时间轴
  - 下半区：建议与求助两列卡片
- Top Timeline:
  - 4月：深化AI研发实践
  - 5月：沉淀项目级context
  - 6月：推进营销活动平台核心能力
  - Q2末：完成核心建设目标
- Bottom Left:
  - 建议：支持AI研发规范沉淀
  - 建议：为平台化事项预留稳定排期
- Bottom Right:
  - 求助：跨团队协同支持
  - 求助：数据指标与复盘支持
- Visual Notes:
  - 时间轴使用深蓝主线，节点用 Accent 色
  - 建议和求助要分栏，避免信息混杂

## 12_ending

- Page Goal: 收束全场，完成转正申请和问答引导
- Layout Type: 总结页 + 结尾短句
- Recommended Structure:
  - 顶部：感谢标题
  - 中部：3条总结
  - 底部：转正申请或 Q&A 提示
- Three Summary Lines:
  - 已证明岗位匹配度
  - 已体现结果导向和复用意识
  - 具备继续承担更大职责的潜力
- Visual Notes:
  - 页面要轻，避免信息过满
  - 结尾可保留大面积留白，增强收束感

---

## Overall Visual Guidance

- Title Bar: 每页顶部使用统一深蓝标题条，高度保持一致
- Key Insight Bar: 每页标题下方增加一句结论条，浅蓝底
- Card Style: 统一使用圆角轻描边卡片，不要厚重阴影
- Text Density: 每页主内容控制在 3-6 个信息单元，避免堆字
- Data Style: 所有核心数字放大，优先呈现“前后对比”和“结果值”
- Footer: 左侧放项目名，右侧放页码
